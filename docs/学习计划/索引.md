# Pi Agent 学习计划索引

## 这套计划解决什么问题

这套计划面向有生产系统经验的 Python 后端开发者。目标不是学会调用一次模型 API，也不是先学会修改 TUI，而是建立三层能力：

1. 能从源码解释 Agent 的完整运行机制：消息、流式事件、工具调用、循环、状态、取消、重试、会话和上下文压缩。
2. 能用 Python 独立实现一个最小但完整的 Agent，并通过 RPC 或自建适配层与 pi 对照验证。
3. 能把一个窄而真实的业务场景做成 L1 内部只读原型和生产评审包，并知道继续推进到 L2–L4 生产 Agent 还缺哪些证据。

计划基于以下仓库基线整理：

- 分支：`luke-learn`
- 提交：`96617628e85227dedc05095717fbb1b7e878a975`
- `pi-ai`、`pi-agent-core`、`pi-coding-agent`、`pi-tui` 版本：`0.85.1`
- 核验日期：2026-09-08

本文列出的 faux/纯本地聚焦命令已在该基线上实际验证，未调用真实 Provider：Day 1 faux 工具用例 1/1、`pi-ai` 3 files/37 tests、经典 agent 2/45、SDK/RPC 4/21、session/compaction 4/86、Harness 3/65，全部通过。两组 coding-agent 命令有重叠测试，数字不可直接相加；仓库升级后以重新运行结果为准。

以后仓库升级时，应先重新核对[资料索引](./资料索引.md)中的“文档漂移与版本核验”，不要假设本文中的符号和行号永久不变。

## 推荐学习路线

```text
pi-ai
  模型目录、Provider、统一消息、流式事件、工具 Schema
    ↓
pi-agent-core
  Agent 循环、工具执行、状态、队列、取消
    ↓
pi-coding-agent
  SDK、内置工具、扩展、会话、压缩、RPC、产品层
    ↓
生产工程
  权限、隔离、幂等、可观测、评测、部署、灰度
    ↓
耐久性概念与运行时 ADR（第 10 周必修）
  ├─ 选择 classic loop 或 Python runtime → L1 内部只读原型 + 生产评审包
  └─ 选择 AgentHarness → 先完成 Harness 源码与崩溃恢复实验（format 4，WIP）→ L1

L1 之后：开放 L3 写副作用前补完 Harness 对照实验（如尚未完成）
```

`pi-tui` 是表现层选修，不是理解 Agent 的起点。第一次跟踪运行链路时使用 print 或 JSON 模式；它们比 6000 多行的交互模式更容易观察。

学习过程中同时走两条线：

- TypeScript 源码线：理解 pi 当前真实实现，测试用例作为可执行规格。
- Python 复刻线：用 Pydantic v2、`asyncio` 和严格类型重新实现核心机制，证明理解可以迁移，而不是只会照着 TypeScript 阅读。

Python 复刻不是零散代码片段。工程目录、依赖、严格类型、scripted/faux Provider、异步不变量和统一验收命令见[Python 复刻实验工程](./Python复刻实验工程.md)。

## 12 周总览

默认投入为每周 8–10 小时。阶段按验收结果推进，不按日历自动毕业。

| 周次 | 阶段 | 核心问题 | 主要产物 |
| --- | --- | --- | --- |
| 第 1 周前半 | 阶段 0：建立地图 | 一次 prompt 究竟经过哪些层？ | 调用链图、术语表、两条事件 trace |
| 第 1 周后半至第 2 周 | 阶段 1：`pi-ai` | Provider 差异如何被归一？ | 消息模型、事件归约器、Provider 对照笔记 |
| 第 3–4 周 | 阶段 2：Agent Loop | 模型、工具、队列和取消如何形成受控循环？ | Python 最小 Agent、状态图、确定性测试 |
| 第 5 周 | 阶段 3A：SDK 与 RPC | 如何在应用或 Python 服务里控制 pi？ | SDK 实验、健壮 RPC 客户端设计 |
| 第 6 周 | 阶段 3B：工具与扩展 | 副作用、权限、并发、截断如何治理？ | 只读工具切片、威胁模型、失败矩阵 |
| 第 7 周 | 阶段 3C：会话与压缩 | 已落盘且可解析的会话历史与模型上下文为何不是一回事？ | v3 JSONL 解析器、分支/压缩实验报告 |
| 第 8 周 | 阶段 4（上半）：错误与恢复 | 重试、超时、取消、溢出分别在哪一层？ | 故障注入矩阵、幂等策略 |
| 第 9 周 | 阶段 4（下半）：评测与可观测 | 如何用小规模真实样本发现回归？ | 课程评测集、模型侧对照、指标与回归门禁草案 |
| 第 10 周 | 阶段 5：耐久性与选型 | 如何处理进程死亡与未知副作用结果？ | 持久状态机 ADR、运行时选型 ADR；Harness 实验按条件选修 |
| 第 11–12 周 | 阶段 6：结业项目 | 如何把窄场景贯通到 L1 评审？ | 真实仓库诊断 Agent、L1 内部只读原型、生产差距清单 |

## 学习方法

### 1. 每个概念都完成四次闭环

```text
先运行观察 → 再读类型和测试 → 然后读实现 → 最后用 Python 复刻或故障注入
```

只读实现容易陷入局部细节；只跑示例又容易把 SDK 调用误认为 Agent 原理。

### 2. 使用源码真值优先级

发生冲突时按以下顺序判断：

```text
当前源码、导出类型、可运行 examples
> 聚焦测试
> package README 和 docs
> CHANGELOG
> 较旧博客或第三方文章
```

文档仍然重要，但它描述的是某个时点的设计。当前仓库中已经存在少量示例名称和兼容 API 漂移，详见[资料索引](./资料索引.md)。

### 3. 分清稳定实现与演进设计

- 当前学习和集成主线：`AgentSession → Agent → agent-loop.ts`，会话格式是 v3 JSONL 树。
- 进阶研究线：`AgentHarness` durable runtime；其 JSONL storage format 4 仍为 WIP，且有明确未完成项。
- `AgentTool.replay` 只被 Harness 的恢复逻辑使用；经典 `agent-loop.ts` 不会因此自动获得崩溃恢复能力。

不要把 Harness 规范中的目标能力写成稳定主路径已经交付的事实。

### 4. 测试分成两类

- 自动回归：使用仓库的 faux provider，覆盖事件、并发、错误和取消；不调用真实模型，不消耗付费 token。
- 人工观察：在已配置凭据且明确控制预算时，用真实 Provider 看一次无工具 SSE；模型工具选择实验等阶段 3B 的 sandbox 与凭据隔离完成后再做。

业务语料、脏数据和评测案例应来自真实或脱敏真实样本。faux provider 是确定性协议测试器，不是用来伪造业务数据。

## Day 1 与 Day 2 启动清单

Day 1 只做以下事项：

1. 阅读根 `README.md`、`packages/ai/README.md` 和 `packages/agent/README.md` 的概览。
2. 按[分阶段学习计划](./分阶段学习计划.md)阶段 0 的受控命令，用 `--no-tools --mode json` 做一次可选的真实 Provider 最短路径观察，再在无网络 namespace 中运行 faux Provider 的工具调用测试并记录事件流。阶段 3B 建立文件和凭据隔离前，不让真实 Provider 调用文件工具。
3. 从 `packages/coding-agent/src/modes/print-mode.ts` 追到 `AgentSession.prompt()`、`Agent.prompt()` 和 `runLoop()`。
4. 画出“用户消息 → assistant tool call → tool result → 下一次模型调用 → agent_end”的时序图。
5. 不读 TUI、不做多 Agent、不接 RAG，也不尝试先设计公司级通用框架。

Day 2 用 `packages/agent/test/agent-loop.test.ts` 验证你的时序图。如果无法解释事件顺序和内外两层循环，就继续停留在阶段 0。

## 最终毕业标准

只有同时满足以下条件才算完成本计划：

- 能不看源码口述从 `pi-test.sh` 到 Provider adapter 的主调用链，并指出每层职责。
- 能解释 `entries → Agent state → run-local → transformed AgentMessage[] → pi-ai Context → Provider-native payload` 的多层投影链。
- Python 最小 Agent 能处理严格 Schema、未知工具、异常、并发结果排序、steering、follow-up、最大轮次和取消。
- 能说明普通 session resume 与 in-flight durable recovery 的差别，并处理副作用“结果未知”。
- 已通过 ADR 明确选择“Python 控制平面 + pi Node worker”或“Python-native runtime”，结业项目不存在两套 loop 所有权不清的问题。
- 结业 Agent 使用真实或脱敏真实数据，有小规模可复现课程评测集、成本与延迟指标、权限和审计边界。
- 完成 L1 内部只读原型、故障注入与生产评审包；具备 sandbox、预算、审计和 kill switch 的可验证证据。
- 能明确列出扩大生产评测集、真实 shadow/canary、写副作用、HA 和灾备尚需完成的负责人、依赖与门禁，不把课程演练冒充上线证据。

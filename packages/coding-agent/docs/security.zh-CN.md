# 安全

Pi 是一个本地编码 agent。它使用启动它的用户账户权限运行，并将该用户可写的文件视为处于同一本地信任边界内。

## 项目信任

项目信任控制 Pi 是否加载项目本地设置、资源、包和扩展。它不是沙箱，也不会限制你开始在某个目录中工作后模型可以要求工具执行的操作。

当 Pi 从当前工作目录发现以下任一内容时，会认为该项目包含需要信任的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或其祖先目录中的项目 `.agents/skills`

仅有一个空的 `.pi` 目录不算作需要信任的项目资源。

在包含需要信任资源的项目中启动交互式会话时，如果当前目录及其父目录都没有已保存的决定，Pi 会遵循全局设置中的 `defaultProjectTrust`。默认值为 `"ask"`，在 UI 可用时会询问是否信任该项目。保存的决定按规范化目录存储在 `~/.pi/agent/trust.json` 中；应用全局默认值之前，会采用当前路径或父路径上距离最近的已保存决定。

信任项目后，Pi 可以加载需要信任的项目资源，包括：

- `.pi/settings.json`
- `.pi` 资源，例如扩展、技能、提示模板、主题和系统提示文件
- 通过项目设置配置但尚未安装的项目包
- 项目本地扩展和由项目包管理的扩展

拒绝信任会跳过受保护的资源。除非已禁用上下文加载，否则无论项目是否受信任，都会加载 `AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md` 等上下文文件。在信任状态确定之前，Pi 只加载上下文文件、用户/全局扩展以及通过 CLI `-e` 指定的扩展。用户/全局扩展和 CLI 扩展可以处理 `project_trust` 事件；第一个返回“是”或“否”决定的扩展将决定最终结果。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不会显示信任提示。如果没有适用的已保存信任决定，`defaultProjectTrust: "ask"` 和 `"never"` 会忽略这些资源，而 `"always"` 会信任它们。使用 `--approve`/`-a` 或 `--no-approve`/`-na` 可以覆盖单次运行的项目信任设置。

## 无内置沙箱

Pi 不包含内置沙箱。内置工具可以使用 Pi 进程的权限读取、写入和编辑文件，以及运行 shell 命令。扩展是以相同权限运行的 TypeScript 模块。包安装、shell 命令、语言服务器、测试命令和其他开发者工具的行为都与普通本地进程相同。

这是有意为之。Pi 旨在操作本地源码树、调用项目工具链，并与用户现有的开发环境集成。进程内的不完整沙箱很容易被误认为安全边界，但它仍然依赖宿主机 shell、文件系统、包管理器、凭据和扩展代码。真正的隔离必须由操作系统或虚拟化/容器边界提供。

项目信任仅用于控制输入加载。它可以防止仓库在你批准之前悄然更改 Pi 的设置或扩展，但无法保证不受信任的代码、提示或模型输出安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入是本地 agent 的预期风险，Pi 无法可靠阻止。

## 运行不受信任或无人监控的任务

对于不受信任的仓库、你不准备密切监控的生成代码或无人值守的自动化，请在受控环境中运行 Pi。可以使用容器、VM、微型 VM、远程沙箱或受策略控制的沙箱，并且只向其中提供任务所需的文件和凭据。

[容器化](containerization.zh-CN.md)文档介绍了常见方案：

- 在容器或沙箱中运行完整的 `pi` 进程
- 在宿主机上运行 Pi，同时将内置工具的执行转发到 Gondolin 微型 VM
- 仅挂载 agent 应当访问的工作区路径
- 除非容器需要访问宿主机会话、设置和凭据，否则不要挂载宿主机的 `~/.pi/agent`
- 仅传入必需的 API key，或使用短期凭据
- 任务不需要网络时限制网络访问
- 将结果复制回受信任系统前，审查差异和输出

如果以读写方式绑定挂载宿主机工作区，容器或 VM 内的写入仍然可以修改宿主机文件。需要更强的意外写入防护时，请使用只读挂载，或将文件复制进出沙箱。

## 报告安全问题

如需报告安全问题，请遵循仓库的[安全策略](https://github.com/earendil-works/pi/blob/main/SECURITY.md)。请勿为涉及安全的报告创建公开 issue。

本地 agent 的预期行为、缺少内置沙箱、来自不受信任内容的提示注入，以及用户安装的扩展或技能的行为，通常不属于安全边界问题；除非报告证明存在真实的权限边界绕过，或说明 Pi 如何授予本地用户原本不具备的访问权限。
